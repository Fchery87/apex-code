## Design decisions settled here

- Tokens store as the existing `OAuthCredential` shape under key `mcp/<server>` (`refresh: ""`
  when the server issues none, so the shared credential shape stays valid). `tokenEndpoint`
  and `resource` ride in the credential's index-signature extra fields, so refresh skips
  re-discovery; discovery is only the fallback for credentials written without them.
- The connector takes the session's `CredentialStore` — host resolves to `AuthStorage`
  (direct, lock-serialized writes), a sandbox child to `SandboxAuthStorage` (reads from the
  read-only projection, writes through the supervisor channel), and no channel means
  `modify` throws, which is the fail-closed path ADR 0015 already built.
- Typed errors (`McpOAuthRequiredError`, `McpOAuthRefreshError`) pass through the `mcp`
  tool's catch un-wrapped, so the structured message names `apex-code mcp auth <server>`
  without the generic "is unavailable" prefix. A missing token throws before the transport
  is constructed, so no OAuth endpoint is ever contacted from a tool call.
- `auth` parses at server level (like `lifecycle`), never in `transportIdentity`, so every
  existing metadata cache key is unchanged; a test pins that.
- `auth` on a stdio server is a diagnostic ("only supported on HTTP servers; ignoring").
